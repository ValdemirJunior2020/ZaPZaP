# NexusSales AI — go-live checklist (16 Nov 2026)

## What has been coded and deployed
- Public homepage: real Supabase email/password signup (required business name, email, phone) and signed-in owner workspace.
- Owner-only store profile, product/service CRUD, prices, images by HTTPS URL, permanent short SmartLinks (`/s/my-business`), QR/SMS/email sharing.
- Public storefront reads server-side Supabase store/offerings, not customer browser localStorage.
- Real AI via Ollama Qwen3 through a secure authenticated HTTPS gateway; answers come from the **server-verified** business catalog only.
- Server-side 48-hour trial starts **only after successful provider inference and first publication**, does not reset on browser changes.
- 100 AI messages per trial day, 1000 per paid day, atomic database quota; per-IP throttling.
- Customer quote inquiries stored in `nx_leads` for the matching business; private owner inbox.
- Optional Shadow DOM website widget; public bot ID, server-side trial / $228 bundle gating.
- PayPal Sandbox subscriptions: Core $149/month, core + widget $228/month; verified webhooks and checkout disabled until activation.
- Super Admin is separate from public signup; existing PIN entrance is not production-grade MFA.

## Blocking infrastructure — cannot be invented
1. A NEW dedicated Supabase project, NOT The Good Side. The user must specify the Supabase organization, and approve any applicable project cost.
2. A secure publicly reachable HTTPS Ollama gateway to the owner's Qwen3 model. Keep the gateway authentication token secret in Netlify. Do not expose Ollama's port 11434 directly.
3. PayPal sandbox credentials and two ACTIVE recurring plans ($149 and $228) to fully test checkout. No automatic charges until explicitly enabled.

## Netlify environment variables
Open https://app.netlify.com/projects/zapzap-bot/configuration/env and add values scoped to PRODUCTION FUNCTIONS, then redeploy.
- `NEXUS_SUPABASE_URL` = https://YOUR-PROJECT-REF.supabase.co
- `NEXUS_SUPABASE_PUBLISHABLE_KEY` = public `sb_publishable_...` key
- `NEXUS_SUPABASE_SECRET_KEY` = private `sb_secret_...` key; **secret, functions only**. `NEXUS_SUPABASE_SERVICE_ROLE_KEY` legacy fallback also supported.
- `NEXUS_OLLAMA_URL` = dedicated HTTPS reverse-proxy/tunnel base URL for the Qwen3 Ollama service (must be a root HTTPS URL, e.g., `https://your-secure-gateway.example.com/`)
- `NEXUS_OLLAMA_GATEWAY_TOKEN` = strong secret token enforced by the HTTPS reverse proxy before allowing `/api/chat`; **secret, functions only**
- `NEXUS_OLLAMA_MODEL` = `qwen3:8b` (default; the model must already be installed on your machine or hosted GPU)
- `NEXUS_LIVE_CHAT_ENABLED` = `true` only after the secure Ollama gateway is reachable, authenticated, and tested.
- No OpenAI key is used or needed.

PayPal (do not enable billing until sandbox E2E test):
- `PAYPAL_MODE=sandbox`
- `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` (secret), `PAYPAL_PLAN_ID` ($149 USD/month), `PAYPAL_WIDGET_BUNDLE_PLAN_ID` ($228 USD/month), `PAYPAL_WEBHOOK_ID`
- `NEXUS_BILLING_ENABLED=false` until sandbox acceptance, cancellation, upgrade, webhook verification and receipts have been tested.

## Operational notes
- AI replies are generated by the user's Ollama Qwen3 model through an authenticated HTTPS gateway using the company's published data. If Ollama runs on the owner's Windows PC, that computer, Ollama, and its internet connection must remain online for public customers. For production uptime, the same model can run on an always-on private GPU host behind the gateway.
- The AI key and Supabase secret never appear in the browser. Public widget bot ID is NOT an API secret.
- Netlify 'ready' means the build deployed, not that external accounts/provider/payments are working.
- Never configure this against `The Good Side` Supabase project.

## OLLAMA ONLY — critical network boundary
Netlify cannot call `http://127.0.0.1:11434` on your Windows computer. A configured HTTPS reverse proxy or managed secure tunnel must authenticate the `Authorization: Bearer ...` token and forward requests privately to `http://127.0.0.1:11434`. Ollama itself does not enforce bearer-token authentication by default. Never expose port 11434 to the public internet, or disable verification for convenience.

Do not reuse The Good Side project or any service carrying unrelated user information as the bot gateway. Create a dedicated NexusSales gateway. The Netlify function only accepts the configured server-side origin, not customer-supplied URLs. Browser clients never get the token.
